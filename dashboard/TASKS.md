# 任务与工作台清单

Dashboard 内嵌 Obsidian Tasks 8.5.0，沿用其任务模型、缓存、查询、状态、循环、依赖、编辑器和笔记交互。今天、项目、课程和日历提供前端入口；Apex 清单读写所属工作台 Markdown。

## 内容与入口

| 内容或入口 | 职责 |
| --- | --- |
| Tasks 任务 | 普通来源笔记中的任务，识别遵循用户全局过滤配置；相同文字的不同任务分别保留 |
| Apex 清单 | 工作台中的清单卡片，独立维护顺序、层级、勾选、折叠和进度 |
| 待办分区 | 全部未完成、今日、逾期、未来、未安排、已完成、已取消、自定义查询与保存视图 |
| 今天 | 日期关联与逾期提醒；分别显示计划、截止、提醒和跨日安排的原因 |
| 项目、课程 | 按任务关联筛选；新建任务继承入口的上下文 |
| 日历与每日议程 | 安排日期与时间；新建任务按用户配置添加过滤标记，并显示普通笔记保存位置 |
| 清单卡片 | 层级、折叠、拖动、模板、局部进度与提醒；归档内容保存在所属工作台，日记入口保存引用 |
| `tasks` 查询块 | 兼容 Tasks 查询语法、排序、分组、限制、依赖和自定义查询 |

新增分区面板提供一个“待办”选项。旧 `alltasks` 分区继续使用这个实现；现有布局、分区名称和未知配置保留。

今天显示有日期关联的行动；待办页面提供完整检索与历史。课程、项目入口预填两种关联，保存位置在表单内明确显示。日历默认新建计划日期，内容、状态、日期事实与课程／项目范围分别筛选，每个工作台日历分区独立保存。日列表中同一任务只出现一次；时间网格分别显示该任务的计划、截止、提醒等时间事件。

## 状态与日期

任务复选框遵循 Tasks 配置的下一状态顺序。Apex 清单使用简单勾选和父子进度规则，清单文字中的任务标记、日期或循环描述不改变勾选行为。

计划、截止、开始、完成、取消、提醒及跨日安排分别保存。任务所在日记的日期默认不推断为计划日期；可在待办设置中明确开启文件名日期推断。日期编辑与详情窗口支持时间，时间和提醒字段独立于截止日期。

完成循环任务依据上游规则保留执行记录并生成后续项，遵循用户配置的顺序。提醒和跨日结束日期按后续项的日期偏移更新。Dashboard 文件写入保留子项，并在来源引用需要时维护独立标识；笔记编辑沿用 Tasks 的编辑行为。

任务统计、查询、日历、提醒及笔记编辑入口排除由 YAML 布尔值 `dashboard: true` 标识的工作台，支持任意路径、文件名和多个工作台；安全副本、Source、Source Text、Digest、代码示例、派生导航、系统模板和报告、查询视图继续排除。标题、层级、笔记属性和链接由上游索引保留。任务视图遵循 Tasks 全局查询，并应用各入口声明的范围。旧清单视图提供工作台入口。

Tasks 设置为配置权威，单向导出 `system/views/Tasks.md` 中的 `task_statuses` 和 `task_projection`，供 Engine 读取状态类型、任务标记及格式。Engine 排除工作台；配置含全局查询时，Engine 明确报告无法解释该查询，完整查询由 Dashboard/Tasks 执行。任务原 Markdown 继续为内容权威。

## 操作

- **详情**：上游编辑器处理任务字段，保留字段显示和访问键设置；外围表单处理提醒、时间、课程／项目关联和保存位置。取消与关闭不会保存；失败保留窗口和输入。新建任务的标识在保存时创建；写入后刷新失败时，按原内容重试仅继续刷新，不重复写入。
- **来源**：定位实际任务位置，支持独立标识及来源文件变化。
- **加入当日日记**：加入原任务的链接，继续操作原任务。
- **复制为独立日记任务**：创建独立身份，重新映射内部依赖，保留外部依赖。
- **移动**：移动完整 Markdown 子树，保留任务身份、字段和课程／项目关联，并更新指向任务的链接。来源并发变化时撤销尚未完成的目标插入，保留外部修改。
- **归档**：保存完整任务内容和子项，保留字段与标识，并更新已有任务链接；已完成历史仍可查询。
- **高级查询**：附加查询与当前视图及课程／项目范围取交集；自定义查询提供独立查询入口。保存视图保留查询和范围，支持改名、更新与删除。查询错误直接显示，不伪装成空列表。
- **提醒**：Tasks 提醒扩展只读取任务来源；Apex 提醒只读取工作台清单。任务多个入口共用一次提醒；关闭确认后不会在重启或移动任务后重复提示，重新安排时间会产生新的提醒。

提醒由运行中的 Obsidian 检查；重新启动后会发现已到期、尚未确认的提醒。

## 独立 Tasks 的接管

首次接管读取原 Tasks 的设置，优先保留 Dashboard 已有设置，保留原配置文件。独立 Tasks 正在运行时，显示“切换为统一待办”；用户执行切换后停用独立插件并启动统一交互，避免两套笔记任务写入服务同时运行。

全局过滤条件支持空值和用户自定义内容；标签查询、任务格式、状态顺序、日期推断与编辑设置遵循上游。命令“检查任务范围与历史配置”列出工作台中带历史 `#task` 标记的条目，以及当前配置与原独立 Tasks 配置的差异。命令提供来源定位，迁移实际内容需要另行明确范围和授权。

## 开发与验证

`vendor/tasks/` 保留固定上游版本与许可；适配代码位于 `tasks-integration/`。`npm run build:tasks` 使用源码生成忽略的 `tasks-generated/`，构建再合并入单个 Dashboard 插件。不要手工修改生成文件。

`npm run check` 同时检查 Dashboard 和 Tasks 适配及上游类型；`npm test` 重建 Tasks 后运行 Vitest；`npm run build` 构建生产包。跨语言任务样例位于 `tests/fixtures/tasks/task-cases.json`，Engine 的投影、Ruff、Pyright 和根检查共同核验任务范围。

实机验收使用固定 `OKF-Test` 与其独立 Obsidian profile。开发与验收不部署到正式 Vault，不修改正式用户内容。
