## 已确认

### DEC-001 保留现有能力

- 状态：`confirmed`
- 范围：产品能力与用户工作流
- 用户表达：现有功能基本都要保留。
- 决策：优化以简化、统一和提高内容价值为主，不通过删除现有能力解决复杂度。
- 边界：保留能力不等于每个模板区块都默认展示，也不等于重复插件或重复实现必须永久保留。

### DEC-002 使用案例驱动访谈

- 状态：`confirmed`
- 范围：本次个性化设计过程
- 用户表达：不想回答抽象的未来目标和领域优先级。
- 决策：停止追问抽象目标、排序和量表；使用真实材料、短原型和具体操作场景校准。

### PREF-001 学习内容优先于形式

- 状态：`confirmed`
- 范围：Study Guide、Lesson 整理及相关学习提示词
- 用户表达：生成辅助学习材料时过于形式化，实际帮助不大，格式反而成为干扰信息。
- 决策：默认由内容决定结构，不为了模板完整而生成栏目、表格、清单或总结。
- 尚未确认：更偏好连续解释、问题驱动、实现驱动还是考试驱动；需用原型判断。

### PREF-002 高自治、低人工维护

- 状态：`confirmed`
- 范围：全局交互与后台工作流
- 用户表达：希望尽可能少地进行人工主动维护；相信 AI 在事先设计完善后能够可靠工作。
- 决策：目标唯一且结果可校验时，系统应自行检索、决策、执行、验证和汇报，不逐项询问格式或机械参数。
- 实现要求：同一偏好只配置一次；升级、索引、校验和普通故障恢复尽量自动完成。

### PREF-003 接受完全权限

- 状态：`confirmed`
- 范围：本地 OKF 工作流的执行权限
- 用户表达：认为最小权限方案过于保守，可以接受完全权限。
- 决策：不把频繁审批作为默认交互；保留当前高权限方向。
- 实现要求：用后台自动预检、checkpoint、原子写入、Contract/链接校验、审计和失败回滚保证可靠性，不把维护负担转移给用户。

### PREF-004 无 blanket prohibition

- 状态：`confirmed`
- 范围：改写、推断、任务提取、拆分、删除和输出长度
- 用户表达：此前列举的这些行为都可以接受。
- 决策：不把这些能力设为全局禁区。
- 边界：“可以接受”不等于所有场景默认触发；具体触发条件通过案例确定。推断出的事实或偏好应可追踪、可修正，删除应可恢复。

### CONTEXT-001 当前内容领域

- 状态：`confirmed`
- 范围：近期原型和验收材料
- 用户表达：目前还没有实际笔记，主要内容会是 AI、LLM 和药学相关课程。
- 更正：这里的“没有实际笔记”是没有用户正式学习笔记，不是项目里没有生产/UAT 产物。现有产物可用于定位结构问题和做回归；不能直接代表用户偏好。
- 决策：使用现有 AI 相关真实剪藏启动第一轮原型；药学领域仍需以后取得一份真实课程材料。测试笔记和外部剪藏本身不作为偏好证据，用户对原型的反馈才是证据。

### UX-001 多入口并用

- 状态：`confirmed`
- 范围：Dashboard、Claudian、Obsidian 命令面板
- 用户表达：所有入口都使用，主要使用 Dashboard、Claudian 和命令面板。
- 决策：不要求选择唯一入口。三个入口共享同一操作 ID、偏好解析、提示词版本、Contract、写入流水线和结果状态；入口只负责不同的启动体验。

## 当前设计假设

以下内容尚未成为永久偏好，将通过具体原型验证：

1. 学习正文采用最小骨架：标题、原始记录、内容驱动的 AI 正文；问题、练习、表格、代码和任务按需出现。
2. 不默认生成学习目标、术语表、完整摘要、固定题库、复习建议和下一步清单。
3. AI/LLM 材料优先解释机制、架构、数据流、代码/公式的实际作用及版本条件。
4. 药学材料优先保留准确术语、机制链、适用条件、易混点、来源和不确定性，但不把这些信息包装成固定表格。
5. Dashboard 适合选择对象和查看状态，Claudian 适合对话与复杂编排，命令面板适合一步触发；输出语义不随入口变化。

## 高自治的后台执行合同

用户不需要为普通本地操作反复确认。系统内部采用：

```text
预检 → checkpoint → 原子执行 → Contract/链接/原文保护校验 → 审计 → 提交
                              └─失败──> 自动回滚
```

多入口提交统一操作信封，至少包含 operation ID、目标、参数、入口、偏好版本和幂等键，避免重复执行和相互覆盖。
