# OKF Workspace 0.9.2

Windows production deployment can now run independently of the development checkout.

- Package the Engine wheel, locked runtime dependencies, Dashboard and Claudian
  artifacts, and deployment scripts with `scripts/package-workspace-deployment.ps1`.
- Install into a version directory outside the repository. Plugin Python paths and
  scheduled tasks use that directory. Runtime installation does not require npm or
  the component source trees.
- Load Vault resources and Skills from the installed wheel and verify installed
  Engine files against the wheel before recording a deployment receipt.
- Reinstall a retained package to switch versions while preserving the Vault,
  State, tokens and user settings. Data rollback across schema changes still
  requires the corresponding recovery procedure.
- Initialize a new Vault before writing its ownership marker, fixing first-time
  installation into an empty directory.
- Include the release artifacts, deployment configuration and service credentials
  in encrypted Windows backups, excluding the Restic password and rebuildable
  environments. Scope retention and restore selection to each installation.
- Accept an absolute Restic executable path so scheduled backups do not depend on
  the interactive shell's PATH.
- Retry Windows test fixture cleanup when a just-exited CLI still has an open
  executable handle.

Components remain Engine 1.12.0, Dashboard 1.18.0, Claudian 2.3.6-okf.5 and
Workspace schema 3. See [deployment](../DEPLOYMENT.md#install) for installation.

Existing LiveSync/CouchDB and tablet acceptance confirmed by the user can be
carried forward. This deployment change does not require repeating those scenarios.
