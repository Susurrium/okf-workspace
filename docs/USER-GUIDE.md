# 工作台使用指南

[文档索引](README.md) · [部署与配置](DEPLOYMENT.md)

## 常用操作

| 想做什么 | 操作 |
|---|---|
| 写今天的事 | “记到今日日记”，直接在日记中书写 |
| 先记下一个想法 | “快速记录”，保存到待处理；可关联课程或项目 |
| 把工作台便签留作后续整理 | “移到待处理”，保存记录并移除原便签 |
| 导入文件或整个文件夹 | “导入资料”，检查文件清单、用途和归属后提交 |
| 准备学习 | 在学习页生成辅助学习材料，完成后打开学习笔记 |
| 讨论或修改笔记 | 打开 Claudian，或使用内容旁的 AI 操作 |
| 整理可复用的知识 | “整理为知识笔记”，也可直接从资料开始 |
| 查看失败或排队中的任务 | “后台与诊断”的“后台处理”，或当前对象旁的恢复操作 |
| 查找只作参考的资料 | “资料”，搜索后打开原件、正文、用途与关联成果 |
| 浏览正式待办 | 打开“待办”，选择日期范围、状态、历史或保存视图 |

“已选择学习”记录你的用途选择；生成完成不会自动标记学完。“打开核验”只打开笔记，核验应以实际检查来源为准。待处理页的“移到回收站”会移动记录文件；订阅中的“不保留”只记录选择，不另存资料笔记。

工作台备份包含当前工作台和部分组件数据，不是整个笔记库的备份。Claudian 的受限访问范围由设置决定；完整访问不逐次请求批准；计划模式不等同于只读。

下面说明各流程与文件位置。数据类型、路径和技能调用名只在需要定位或配置时使用。


## 1. 先理解分工

- **Codex**：结合笔记帮助理解、检索、讨论和写作。
- **Vault**：人与 AI 都能读取的长期 Markdown 记忆。
- **Obsidian**：主要阅读和人工编辑界面。
- **工作台**：概览、跳转、导入、捕获和触发任务的快捷入口，不代替原生笔记。
- **本地服务**：转换、Feed、索引和后台任务；关闭 Obsidian 后停止，已有 Markdown 仍完整可读。

### 分区与工作台

工作台右缘的短线提供分区导航：悬停显示名称，点击定位，当前分区保持点亮；键盘可用 Tab 选择并按 Enter 或空格定位，触屏保持可见。没有保存固定偏好时，小组件侧栏默认固定，可通过横幅图钉取消。

新建日常工作台依次展示今天、工作台便签、每日更新、任务周历。学习和项目预设分别组合完整业务功能与便签，订阅阅读组合订阅和微信读书，知识与系统预设提供各自完整业务功能。快捷按钮提供快速记录、新建任务、搜索与快捷操作。工作台切换和侧栏沿用 Apex 原有设计，原生工具按已有启用设置显示。所有业务功能均可通过快捷操作或命令独立打开，也可添加到工作台。

添加分区按日常与行动、资料与阅读、学习与项目、笔记与展示、查询与维护分组。选项只显示图标和名称，可搜索旧名称；名称输入和添加按钮固定在窗口底部。便签、清单卡片和便利贴分别保留，便利贴允许混合放置便签与清单卡片。笔记卡片用于手工组织笔记链接；属性视图筛选现有笔记属性；DQL 查询按查询语句展示结果。

| 分区 | 用途 |
| --- | --- |
| 今天 | 继续工作、今日正式任务、逾期任务和人工待处理提醒 |
| 任务 | Tasks 任务、日期视图、状态历史、高级查询与保存视图；清单项在工作台清单卡片内管理 |
| 收集箱 | Capture 整理与未决定的资料用途；转换记录通过后台入口查看 |
| 订阅阅读 | 来源、最新期次、历史、同步与用途判断 |
| 资料 | 全部已保存 Source、原件、正文、用途、关联成果与导入记录 |
| 学习 | 待准备、可学习、已学完；课程、项目和独立范围 |
| 项目 | 状态、下一步、正式任务、进展、日志、决策和成果 |
| 知识笔记 | Wiki 与 Wiki Map；组合类型、内容状态和维护条件 |
| 日记与复盘 | 日记、反思、周期复盘、类型和日期检索及原生编辑入口 |
| 后台与诊断 | 后台执行与恢复、运行环境诊断两个页签 |

业务分区在工作台和独立页面提供同一组操作。搜索、筛选、排序、切换视图与加载更多均在当前位置完成；高级查询和次要工具可展开，正文与原件通过原生笔记和文件查看器打开。今天聚合今日行动、继续内容和待处理提醒；每日更新聚合所选来源的最近一期，条目可以继续加载。

内容工具栏提供新建、搜索、筛选、排序和视图切换。排序改变当前浏览状态；分区设置中的“默认排序”决定初始顺序。功能分区的临时排序、搜索和筛选不会自动修改工作台配置，独立页面解除某个范围时保留其他当前筛选和排序。标题栏提供打开或放大、适用的刷新和更多菜单；更多菜单提供分区设置、重命名和移除。

分区配置设置持久范围、初始视图和具体数量。普通列表新默认每批显示 10 项，独立页面每批 30 项；订阅来源每批最多 8 个，最新一期的预览数量单独设置。固定的课程、项目、状态和文件夹范围与页内临时筛选共同生效，范围显示在标题栏。标题可以自由修改。新建学习、项目工作台时明确选择总览或一个对象。

箭头控制分区折叠；标题栏的“在新标签页打开当前视图”携带当前已应用的搜索、筛选、视图和排序。功能分区、任务日历、属性视图、文件夹视图、图片、视频和 DQL 查询提供独立页面；卡片分区、微信读书及滴答清单提供放大窗口，继续操作所属工作台。网页还可在浏览器打开。

页面与工作台分别保存浏览状态，返回后恢复原位置；对真实对象的修改会同步显示。功能独立页面可以明确取消继承的范围，该操作不修改原工作台。功能独立页面分别保存返回历史。从关联数量打开目录时，按当前真实关系查询；“预览关联”提供少量对象的直接访问。

旧工作台打开时只读取，不自动改写。历史展示模式用于恢复原有数量，业务功能保持完整；保存某个分区的设置时规范化该分区已识别的字段，保留未知配置、其他分区、标题、布局和正文。旧预设文件继续保留，新预设只用于新建工作台。

日常预设包含一个日历，任务继续保存在来源笔记中。可以主动添加其他日历，并分别设置内容、状态、日期及课程／项目范围；这些日历读取同一批任务，各自保留筛选与显示位置。

收集箱按每个用途上下文显示待判断条目；资料目录中每份 Source 显示一次，详情保留全部用途。学习数量使用“学习条目”，包含待准备、可学习和已学完；同一条目可以同时进入课程、项目关系筛选。选择“课程相关”或“项目相关”后，可展开选择器指定具体对象；课程信息与操作分别显示，窄窗口中的操作自动换行。

原有工作台保持原布局。通过快捷操作或命令可打开全部功能，也可主动调整分区范围。任务日历、项目任务、Today，及不同位置的资料添加、恢复入口保留各自场景；同一任务与操作使用同一真实对象。

快速记录保留未保存草稿，成功保存后清空。导入窗口在当前插件会话中保留未提交文件与处理选择，重新启动后未保存文件需要重新选择；关闭窗口不提交尚未确认的文件。归属可以同时选择课程和项目。

### 外观与小组件

设置中的主题选择包含胶囊及已有主题。命令“打开外观工作室”可直接调整颜色、背景、透明度、模糊、圆角和字号；“保存为主题”保存当前完整外观，之后可在主题选择或工作室中应用、删除。删除已保存主题保留当前外观。

番茄钟齿轮统一打开计时模式、提醒、活动标签和背景设置。倒计时沿用专注与休息周期；正计时累计实际专注时间，暂停时间不计入，提醒间隔为零时不提醒。提醒窗口关闭后继续计时，明确“结束并记录”后按完整分钟保存一次，不足一分钟不记录。运行或暂停中的计时需结束后才能切换模式，迷你计时条同步显示当前状态。

记账分类管理支持预置和自定义分类的增删、排序与分组，每个收支方向至少保留一个分类。删除分类保留已记流水，重新打开后分类与顺序继续生效。音乐播放不再逐曲弹出无权限或无法播放通知，连续失败停止时仍提示。

## 2. 自己写内容放哪里

| 场景 | 位置与做法 |
|---|---|
| 灵感、课程或项目想法、暂不确定归属 | 今天点“快速记录”，输入正文，可同时选择课程和项目，点击“保存到待处理”。关闭窗口保留草稿及关联。 |
| 日记正文 | 今天点“创建/继续写今日日记”或 Chinese Calendar，打开 `life/daily/YYYY/MM/` 中当天的日记。 |
| 记到今天 | 调用“记到今日日记”，创建或打开当天的原生日记，并定位到“随手记录”；内容直接在 Obsidian 中写，不经过工作台输入框或待处理。 |
| 独立感想 | 调用新建反思，给出标题后直接打开 `life/reflections/` 中的原生 Markdown 正文。 |
| 课堂记录 | 先选择已有课程，再创建 `Lesson` 到课程的 `lessons/`。人工原文写在 notes 区。 |
| 项目当前状态 | `projects/<project>/project.md`。 |
| 项目过程 | 项目的“项目日志…”中留空会直接打开原生 `log.md`；填写内容才按时间追加一次。它是纯 Markdown 时间日志，不使用 YAML。 |
| 正式项目决定 | 使用命令“记录项目决策”，只输入标题后打开项目 `decisions/` 下的原生笔记。它是低频正式记录，不占项目列表的高频操作位。 |
| 长期知识 | `knowledge/wiki/` 的知识笔记；多个知识笔记需要主题导航时再维护 `knowledge/maps/` 的知识导航。 |

日记、课堂笔记、学习笔记等受管笔记把个人原文与 AI 可替换区分开。后台只改自己的 `ai:auto` 区域；希望永久保留的个人补充写在普通或 `human:notes` 区。

“快速记录”和“今日日记”不是同一个入口：前者是通用随手记录，适合尚未整理的灵感，
即使选择了课程/项目也仍留在待处理；后者属于当天的生活记录，不进入待处理队列。

### 为什么一篇笔记看起来只有一个标题

同一篇受管笔记有三个不同职责的标题信息，但正常阅读时只显示正文 H1：

```text
life/reflections/重新设计项目入口.md   ← 稳定文件路径
YAML title: 重新设计项目入口           ← Dashboard、搜索和程序读取
# 重新设计项目入口                     ← Markdown 正文中的人类标题
```

Obsidian 的 Inline Title 和正文 Properties 已默认隐藏，因此不会再把文件名、Properties 与 H1
连续显示三遍。文件名不再机械附加日期；只有日记、复盘、课堂笔记、项目决策等“日期本身就是
身份或排序依据”的记录保留日期。YAML `title` 与 H1 内容相同并不是两份正文：前者是结构化数据，
后者保证文件离开 Obsidian 后仍是完整、可读的 Markdown。

## 3. 日记与生活

你可以直接自由写日记。需要整理时，在工作台点“整理今天”或对 Codex 说：

> 使用 `$organize-daily` 整理今天的记录，保留原文，只更新 organized-daily 区域。

系统不会自动改写原文，也不会从日记擅自推断长期偏好。明确的待办仍使用 Obsidian Tasks 语法 `- [ ]`；Tasks/Dataview 负责查询展示，YAML Contract 不复制它们的状态。

阶段复盘从工作台 → 生活点“新建复盘”，再选择 Weekly、Monthly 或 Yearly。系统直接
创建或打开当期 `life/reviews/<周期>/` Markdown，模板引导你回看进展、阻力、变化和下一周期；
不启动后台服务，也不要求 AI。也可以用 Templater 的“从模板新建笔记”选择 `Review`；Templater
只负责首次创建，同周期文件已存在时会拒绝重复创建，已有复盘请从工作台打开。
终端或 Codex 也可使用 `okf note new review --period weekly|monthly|yearly` 创建或打开当期文件。

## 4. 保存原件与转换资料

电脑、手机和平板使用相同的“导入资料”窗口；电脑可拖入文件或文件夹，课程/项目的“添加资料”会带入当前归属。文件夹只是批量选择，不把本机目录结构复制到 Vault。先检查文件清单、跳过项和归属，再提交。单文件上限 64 MiB。

默认选择“仅保存原件”，点击“保存原件”。完整文件立即写入本机 `sources/originals/<sha256>/<原文件名>`，断网也能保存；通过 LiveSync 发送到其他设备。主机 Engine 校验后登记资料，不创建转换任务、资料正文或空白学习笔记。关联课程/项目也不会触发转换或 AI。

需要 Markdown 正文时明确选择“保存并转换正文”，才显示以下设置：

1. **转换方式**：默认 MinerU 云解析，也可使用已配置的 MarkItDown 或自建 MinerU。窗口显示支持格式、服务位置与配置提示；混合文件夹有不支持项时，调整方式或明确跳过这些文件。
2. **质量检查**：标准检查与严格检查图片独立于转换方式，不会自动切换服务或提升解析器能力。
3. **用途**：学习、知识笔记、参考或暂未决定。生成学习笔记或 Wiki 需要额外明确选择生成；稍后生成只保存用途，不创建空白目标。
4. **归属**：从课程/项目选择，也可在窗口中新建；创建成功会保留文件与设置，仍需提交导入。无归属的学习成果进入 `learning/guides/`。

资料卡位于 `sources/records/`，转换后的正文位于 `sources/text/`。同一原件复用资料身份，在 `uses[]` 中记录不同用途和课程/项目；不会为每个上下文重复复制原件。转换进度、失败与重试由电脑 Engine 保存，目标笔记成功生成后才发布。

在“已保存的资料”打开原件、主动转换或查看结果。已有正文时生成笔记会复用正文，失败的生成可以单独重试。重新转换可选择另一种方式；正文已经被人工修改时保留原文，用“查看本次转换结果”查看新 Markdown 与质检报告。正在执行的转换需先等待结束。

MarkItDown 可提取 DOCX/PPTX 常规内嵌图片；其 PDF 路径以文本为主，不提供扫描 OCR 或 PDF 图片提取。扫描页、复杂公式和图示仍需检查原件与转换结果。格式矩阵及配置见[部署运维](DEPLOYMENT.md#conversion)。

### 手机和平板阅读

保持 Tailscale 连接和 LiveSync 开启，等待原件与笔记同步；本机保存成功不等于服务器已收到。电脑 Obsidian 关闭时，其他设备仍能读写本地笔记和打开已同步原件；登记、转换与后台生成需电脑 Engine 运行。

PDF 和图片在 Obsidian 原生打开，不需要原件服务地址、令牌或按需缓存。原件尚未到达时提示等待同步。Office 格式可阅读转换正文，编辑原件时自行选择外部应用。不要直接覆盖哈希归档中的文件；批注或改版另存后再导入。普通附件的“导入为资料”会保留原位置及既有嵌入链接。

旧设备升级先在电脑迁移原件，再同步新版插件与原件，重启 Obsidian。仅同步插件 `main.js`、`manifest.json`、`styles.css`，保留设备自己的 `data.json`、本地路径和密钥。隐藏程序未更新时从 LiveSync Hidden Files 取回；新版会恢复旧 IndexedDB 未完成上传，失败保留数据并提供“重试恢复旧版文件”。完整迁移步骤见[部署运维](DEPLOYMENT.md#original-migration)。

## 5. 网页剪藏

浏览器安装官方 Obsidian Web Clipper 后，导入 Vault 中的
`system/integrations/web-clipper/workspace-web-capture.json`。Interpreter 保持关闭；
模板只把网页全文、选区或高亮写成 `ingested_via: web-clip` 的随手记录，不在浏览器
保存本地 API token，也不调用 AI。

之后在工作台 → 待处理的“网页剪藏”中选择：

- 立即学习：发布资料 + 资料正文，并排队生成学习笔记；
- 稍后学习：在 `uses[]` 增加 `purpose: study`，不创建空白 Guide；
- 生成知识笔记：发布后排队生成知识笔记；
- 仅作参考：在 `uses[]` 增加 `purpose: reference`，不调用 AI；
- 丢弃：移入 Obsidian 本地回收站，不建立随手记录 archive。

不做选择就继续保留这篇随手记录；文件仍在待处理本身就是“待处理”，不需要额外状态。
同一 URL 会忽略 fragment 和常见跟踪参数进行去重；重复选区/高亮合并到资料
Text。图片先用远程链接快速发布，再在后台安全下载到 `sources/assets/`；失败不阻塞。
浏览器一次性配置如下；协议与去重规则见[接口说明](INTERFACES.md#web-clipper)。

### 浏览器配置

1. 安装官方 Obsidian Web Clipper 浏览器扩展，并把当前 Vault 配置为目标 Vault。
2. 打开扩展设置的 Templates，选择 **Import template**。
3. 导入 Vault 中的
   `system/integrations/web-clipper/workspace-web-capture.json`。
4. 确认新导入的 `Workspace · Web Capture` 位于模板列表顶部。模板自带
   `https://` 和 `http://` 触发器，会自动接管普通网页；不要再手动选默认模板。
5. Interpreter 保持关闭；本模板没有任何 prompt variable，也不需要 API Key。

每个浏览器配置一次。模板文件会随 Vault 同步；浏览器扩展自己的设置不由
LiveSync 自动同步，Vault 中的 JSON 更新也不会自动改写已导入的浏览器模板。
如果之前已导入过旧版，请删除旧的同名模板后重新导入；导入操作本身
会把新模板放在列表顶部。

如果曾经误用官方默认模板，笔记会出现在 Vault 顶层的 `Clippings/`，并使用
`source/created/tags: clippings` 这组默认 YAML。运行 Workspace 布局迁移后，系统只会
识别这一精确默认签名，将其安全移入 `inbox/captures/YYYY/MM/`，补齐
`type/title/created_at/ingested_via/resource`，同时保留正文和其它元数据。
非默认结构的个人笔记不会被移动，同名目标也不会被覆盖。

## 6. 学习完整流程

### 学习前

学习笔记位于 `learning/guides/` 或对应课程的 `guides/`。两种生成方式使用同一套 Contract：

- **后台生成**：工作台创建可恢复任务；可切换页面，完成后通知。
- **在 Codex 中生成**：打开可见会话，附带来源和 `$prepare-study-guide`，你可补充要求后发送。

选择“稍后生成”只保存一项 `uses[].purpose: study`，不创建空白目标。以后可从学习的“待生成”卡片点击，也可直接对 Codex 说：

> 使用 `$prepare-study-guide`，根据这份资料和资料正文生成学习笔记。

### 学习中

阅读学习笔记，必要时打开资料正文或原件，在 Codex 中追问和实践。值得长期保留的一轮讨论结束后说：

> 使用 `$update-study-guide` 整理以上对话，增量完善当前学习笔记。

Codex 读取现有内容、来源和本轮结论，补充解释、例子、纠错、已解决与未解决问题，不从头覆盖个人笔记。

### 学习后

完成学习后说：

> 使用 `$distill-wiki` 从这次学习生成或更新知识笔记；我已经完成学习。

Codex 会先检索已有知识笔记，选择新建、更新、合并或拆分，并在你明确声明完成时写 `studied_at`。如果材料有价值但你不想学习，也使用同一个 `$distill-wiki` 直接形成知识笔记；此时不写 `studied_at`。主题知识笔记足够多且关系需要导航时，再调用 `$maintain-wiki-map`。

## 7. 每日更新与订阅阅读

AI 日记是外部生产器名称。新建日常工作台中的“每日更新”独立展示中国热点、AI 资讯和树洞热榜；旧 Today 分区仍可通过配置包含每日更新。每个来源选择自己的最近一期并保留阅读位置，“查看本期全部”打开原生订阅汇总。配置可选择需要的来源。

订阅阅读按 RSS、周刊、教程或工具订阅的真实来源显示小卡片。每张卡片只展示该来源最近一期的日期、数量、待判断数和前几条预览；来源较多时可按来源名称搜索并分页加载。点击“查看该来源”后仍在订阅阅读页面进入该来源，按期浏览完整历史；返回时恢复来源概览位置。订阅阅读是持续累积的候选阅读档案，不是第二个学习。

工作台展示条目的关键摘要和必要元数据；点击条目会打开 Obsidian 原生订阅汇总的准确位置，完整正文、TreeHole 评论和人工判断都沿用同一套交互。浏览订阅内容不会自动创建资料或学习笔记，只有明确选择“想学习”后才进入学习。

系统不替你计算兴趣或价值。每条由你选择：现在学习、稍后学习、直接形成知识笔记、只保存参考或不保留。对应的长期决定写入 `Source.uses[]`，`purpose` 为 `study / wiki / reference`，并可携带明确选择的课程/项目。同一资料可以有多个上下文用途。暂时不能决定时直接离开即可：条目仍在 Feed cache、订阅阅读和原生订阅汇总中，不产生决定回执、资料或 `undecided`。选择“现在”会额外启动后台任务；选择“稍后学习”不会制造空白学习笔记/知识笔记。

订阅包含 Reading 顶部独立的 AI Papers 系统卡片；它不属于可启停的普通订阅。添加普通订阅需先预览再确认；停用或移除停止后续采集，历史内容继续保留。同步配置和动作协议见[接口说明](INTERFACES.md#feeds)。

## 8. 在新 Codex 对话中使用既有知识

Vault 根目录 `AGENTS.md` 负责轻量路由。需要结合既有笔记、继续课程/项目、查找历史决定或回答个人化问题时，Codex 使用 `$retrieve-vault-context`，底层等价于：

```powershell
okf context "你的问题" --scope auto --json
```

检索只定位候选，随后读取真实 Markdown。`actual_reads` 记录本轮真正读取的文件。向量索引损坏或不存在时仍可使用标题、标签和全文检索，不影响 Vault 权威数据。

## 9. 项目流程

1. 创建项目，填写目标、约束和初始计划。
2. 项目行显示当前最常用的操作，例如记录进展、恢复推进或重新开启；其他操作在菜单中。
3. “其他操作”菜单提供项目日志、记录待整理想法、添加资料、记录项目决策和用 AI 整理项目；
   项目状态单独放在分隔线后的低频区域。
4. 执行期间随时讨论问题；需要整理本轮进展时说“使用 `$capture-project-progress` 整理以上进度”。
5. Skill 增量追加 `log.md`，必要时更新 `project.md` 的当前状态；真正需要独立追溯的正式选择再建项目决策。
6. 项目中出现学习需求可调用学习笔记 Skills，出现长期知识可调用知识笔记 Skills。

项目不建立重型状态机。`project.md` 是当前快照，`log.md` 是持久的过程记录，日常使用不依赖 Git。如果你需要额外的本地版本恢复，可以主动启用 Vault Git checkpoint。

## 10. 工作台、模板和插件

工作台是操作入口，Vault 根目录 `index.md` 是移动端或插件不可用时的备用目录。第三方插件增强人工入口和阅读，共享同一份 Markdown；不用它们时真实笔记仍保留。

### Templater

用途：用户主动创建或插入结构。模板目录是：

```text
system/templates/interactive/
```

当前提供 Reflection、Review 和 Project Update。用“从模板新建笔记”执行 `Review` 时会先选择
Weekly、Monthly 或 Yearly，再移动到对应的 `life/reviews/` 路径；若当期文件已经存在则拒绝
重复创建，使用 Dashboard 直接打开已有 Review。Templater 不调用 Codex，Codex 也不“操作 Templater”；
两者共同遵守 `system/contracts/`。日记由 Core Daily Notes 使用
`system/templates/core/Daily.md`，避免 Templater 与 Chinese Calendar 生成不同结构。

安装脚本只设置 `templates_folder`，不启用启动脚本、系统命令或自动整库写入。

### QuickAdd

QuickAdd 可绑定工作台的“统一 OKF 快捷动作菜单”，无需复制路径和 YAML 逻辑。缺少 QuickAdd 时命令面板仍可完成相同动作。开发用 Command ID 见[接口说明](INTERFACES.md#commands)。

### Dataview

用途：在原生 Markdown 页面中动态查询 YAML。预置视图：

- `system/views/Learning.md`；
- `system/views/Projects.md`。

Dataview 结果不是长期正文，不被 Codex 当证据，也不是 Dashboard 的数据源。删除 Dataview 后，
所有真实课程、项目和学习材料仍然存在。

### Tasks

正式任务使用：

```markdown
- [ ] #task 完成一个明确动作
```

任务识别遵循 Tasks 的全局过滤配置；`#task` 是配置使用该标记时的示例。今天按日期关联显示未完成任务，任务页面提供完整检索与完成／取消历史。工作台清单由清单卡片独立维护；来源资料和代码示例中的清单排除在正式任务统计之外。

Dashboard 内置统一 Tasks 模型，共用状态、循环、依赖和 Markdown 写入。点击任务文字编辑详情，点击日期编辑安排，“来源”定位原始行。课程和项目可同时关联；从对象入口新建会预填其范围。高级查询与当前视图取交集，可保存、改名和删除视图。移动保留身份及子项并更新引用；加入日记创建原任务链接，独立复制重新分配身份。完整格式与接管方式见[统一待办](../dashboard/TASKS.md)。

### Recent Files

Recent Files 直接作为 Obsidian 侧栏历史使用。Dashboard 不复制完整历史，只显示“最近学习”、
“最近项目”等有领域含义的入口，因此两者不会争夺同一功能。

### Chinese Calendar

Chinese Calendar 负责日期、农历、节气和完整日历视图。Dashboard Life 页只显示最近日记并调用
公开命令 `chinese-calendar:show-chinese-calendar-view`。从日历点日期时仍落到 Core Daily Notes
配置的同一路径和同一模板，不启用 Chinese Calendar 的 QuickAdd 日记分支。

### Claudian

Claudian 提供可见 Codex 会话、上下文附件和交接界面；方法来自 Vault 中的规则和 Skills。工作台交接会显示会话，任务与附件可以检查、移除和补充，默认预填后由你发送。相关文件 chip 区分资料卡与资料正文，发送按钮旁在生成时显示“停止”；停止会取消当前生成。

每台设备只启用适合本机的插件。安装器只启用本次必需的 OKF 插件与明确提供的 LiveSync，保留其他插件已有的禁用选择。无需本地 Codex 的设备仍能使用模板、任务和日历，并同步笔记。

## 11. 系统状态与多设备

系统状态展示本地服务、解析器、Codex、索引、后台任务、可选 Git checkpoint、备份、Contract、断链、陈旧知识笔记和未复核 AI 知识笔记。Vault 默认不创建 Git 仓库；只有主动执行 `okf checkpoint` 选入后，后续自动化写入才生成本地 checkpoint。正常使用不需要反复校验；部署、迁移和专项审计才跑全库检查。

LiveSync 启用后，其他设备可阅读、搜索、写日记/随手记录、编辑项目与学习内容，并查看已生成结果。本机不必一直开启 Obsidian 才能读取 Markdown；只有本机 Codex、MinerU/MarkItDown 转换、主机索引、后台任务和备份需要主机 Obsidian 运行。
