# OKF 第二大脑个性化深度访谈

> 历史记录（2026-10-06 归档）。下文保留当时的方案、状态和验证证据，不作为当前实现要求；当前边界见[系统架构](../../architecture/README.md#system-overview)，有效文档见[文档索引](../../README.md)。

> 目标：把用户真实的工作方式转化为可执行、可验证、可维护的 Skills、模板、提示词、入口和权限边界。  
> 方式：分轮访谈；每轮只问一组，允许跳过；用真实例子校准，不要求用户一次填写整份问卷。

> 2026-08-24 调整：用户不希望回答抽象目标和优先级问题。后续访谈改为“具体材料 → 两个短原型 → 指出有用、干扰和缺失内容”，不再要求先定义完整理想流程。

## 1. 访谈规则

每个主题都区分四件事：

1. **现在怎么做**：事实，不把理想状态误当现状。
2. **希望怎么做**：目标行为及其优先级。
3. **例外是什么**：什么情况下默认规则不适用。
4. **如何算成功**：可以用真实场景检验的标准。

记录偏好时必须注明：

- 是全局偏好、领域偏好，还是仅适用于某条工作流。
- 是 `confirmed`、`hypothesis` 还是限时 `experiment`。
- 用户原话、确认日期、例外和复查日期。
- 正面示例和不可接受的反例。

以下内容不能自动当作偏好：收藏/剪藏的观点、Feed 内容、测试笔记、AI 生成总结、一次性的临时要求。

## 2. 访谈安排

建议分为 4 次、每次 30–45 分钟；也可以在聊天中逐轮完成。

| 场次 | 主题 | 主要产物 |
|---|---|---|
| A | 真实摩擦、保护边界、具体案例 | 行为假设、保留清单、首个原型 |
| B | 捕获、学习、知识、项目、日常 | 各工作流的默认值和例外 |
| C | AI 协作、权限、提示风格、入口 | 交互契约、模型/成本策略、入口矩阵 |
| D | 信息架构、迁移、验收 | 变更清单、迁移范围、验收与回滚计划 |

## 3. 第 0 轮：现状确认与保护边界

目的：防止优化过程破坏已经好用的部分。

1. 当前系统中最满意、必须原样保留的三点是什么？
2. 哪些功能已经在真实使用，哪些只是搭好但尚未形成习惯？
3. 你目前主要在哪些设备和场景使用：桌面、手机、浏览器、命令行、聊天窗口？
4. 哪些目录或笔记属于敏感区，AI 默认不应读取或只能在明确点名后读取？
5. 哪些现有内容是验收/测试数据？它们需要保留作证据、移到测试 Vault，还是最终删除？
6. 是否存在正式 Vault 之外仍需继续维护的旧库、旧脚本或旧工作流？

## 4. 第 1 轮：目标、优先级与真实摩擦

> 本轮已于 2026-08-24 完成。用户跳过抽象目标和优先级问题；这是有效回答，不应换一种说法重复追问。结果记录在 `PERSONALIZATION-DECISIONS.md`。

1. 未来 3 个月，你希望第二大脑直接帮助实现的三个结果是什么？
2. 请为以下领域排优先级，并指出暂时不做的项：捕获/阅读、学习、知识沉淀、项目推进、Daily/生活、Reflection/Review、自我认知、文档导入、AI 问答。
3. 最近三次“本来想用 OKF，但最后放弃、绕开或手工处理”的具体场景是什么？
4. 目前最浪费时间的三个步骤是什么？每个大约多频繁发生？
5. 你希望每天主动维护系统的时间上限是多少？
6. 什么是系统绝不能做的事？例如改写原话、擅自推断、制造任务、过度拆笔记、自动删除、输出冗长等。
7. 你喜欢的一个笔记/回答范例是什么？不喜欢的一个范例是什么？为什么？
8. 接下来半年最真实的内容领域有哪些？例如课程、医药、AI 编程、研究、工作项目或生活记录。

### 后续访谈执行方式

1. 每次只选择一个真实材料或明确主题。
2. 使用相同事实范围和近似长度生成两个短原型：解释驱动与问题/案例驱动。
3. 用户只需指出更愿意继续读的版本、最想删的一处和最缺的一处。
4. 同一偏好在同领域两次出现后才成为领域默认；跨领域稳定出现后才升级为全局默认。
5. 没有真实材料时使用合成样例，但必须标记为实验，不据此写入永久偏好。

## 5. 第 2 轮：捕获、收件箱与阅读

### 2.1 快速捕获

1. 你会捕获哪些东西：想法、待办、链接、引用、问题、灵感、语音、图片、会议内容？
2. 捕获时愿意填写的最少信息是什么？可以接受几次点击/几秒完成？
3. 捕获应默认进入统一 Inbox，还是按来源/类型预分流？
4. 一条输入何时算“处理完成”：归入 Daily、Project、Source、Wiki、任务系统，还是直接丢弃？
5. 捕获整理后是否保留原始条目？不同类型是否有不同规则？
6. 如果一条输入同时属于项目、学习和 Daily，哪个是主归宿，哪些只建立链接？

### 2.2 Web、Feed 与外部资料

1. 保存网页时，你更关心全文可离线、原链接、摘录，还是自己的批注？
2. 新闻/Feed 是临时阅读队列，还是需要长期归档？保留期限是什么？
3. 什么条件下外部内容值得转为 Source、Study Guide 或 Wiki？
4. 是否自动去重？相同 URL、相似标题和转载内容分别怎么处理？
5. 外部作者观点在回答中应如何标记，才能不与“你的观点/偏好”混淆？
6. 对引用、发布日期、作者、原文片段和可追溯性有什么硬要求？

### 2.3 图片与附件

1. 图片、PDF、音频和其他附件的默认目录与命名方式是什么？
2. 遇到同名或内容重复的附件，应复用、自动改名还是先询问？
3. 是否需要压缩、格式转换、OCR 或移除 EXIF 等隐私信息？哪些操作必须保留原件？
4. 移动附件时，应更新哪些 Markdown、Canvas、Base 或其他引用？
5. 从网页下载远程图片是否必须显式授权？链接失效风险与本地存储成本如何取舍？

## 6. 第 3 轮：学习与知识沉淀

### 3.1 学习

1. 你学习的主要材料类型是什么：课程、论文、书、视频、网页、代码仓库、工作文档？
2. 创建 Course 时，目标、基础、期限、教材、节奏和完成定义中哪些必须当场填写，哪些可以以后补？
3. 不同材料需要不同 Study Guide 吗？请给出最常见的两到三种模式。
4. 默认深度更接近：速览、理解、可复述、可应用、备考，还是研究级？
5. 你喜欢先给全貌、逐节推进，还是先解决当前问题？
6. 哪些内容必须包含：核心概念、先修知识、例子、反例、公式、代码、练习、自测、术语表、来源定位？
7. AI 应在什么时候追问，什么时候可以用明确假设继续？最多连续追问几轮？
8. 如何判定“学会”：用户声明、完成练习、通过自测、能够输出项目，还是组合条件？
9. 学习对话中哪些结论应自动提议回写，哪些只留在会话中？回写前是否需要看差异？

### 3.2 Wiki 与长期知识

1. 你希望 Wiki 更像原子卡片、主题文章、操作手册，还是混合体？
2. 何时创建新 Wiki，何时更新、合并或拆分？
3. 你希望多细的粒度？请给出一个“太碎”和一个“太大”的例子。
4. Wiki 是否必须有来源？个人经验、推理结论和外部事实如何区分？
5. 哪些领域需要 Wiki Map？导航更偏目录、学习路径、概念关系还是项目入口？
6. 未学习但可能有用的资料可以进入长期知识吗？应如何显式标记？
7. 冲突信息如何保留：覆盖旧结论、并列观点、Decision，还是待核验问题？
8. 合并/拆分后，旧笔记应保留重定向、标记 deprecated、进回收站还是立即删除？回滚点保留多久？

## 7. 第 4 轮：项目、Daily、Reflection 与 Review

### 4.1 项目

1. 什么规模的事情才算 Project？短任务、习惯、研究主题分别放哪里？
2. 项目首页最需要一眼看到什么：目标、状态、里程碑、阻塞、下一步、风险、Decision？
3. 一次更新应记录事实时间线，还是同时重写当前状态？
4. 默认保留几个“下一步”？是否必须可执行、带日期或 Obsidian Tasks 语法？
5. 什么情况触发 Decision note？你需要记录备选项、依据、风险和复盘日期吗？
6. 项目关联资料应复制、移动，还是只链接 Source/Wiki？
7. 项目结束后如何归档、复盘和提炼可复用知识？

### 4.2 Daily 与任务

1. Daily 是日志、工作台、收件箱、情绪记录、任务清单，还是它们的组合？
2. `今天` 与 `随手记录` 分别放什么？一句“记录今天……”默认落到哪里？
3. AI 整理时必须逐字保留哪些内容？允许怎样改写和分组？
4. 什么样的句子才应转为任务？不明确的意图应提问、保留原文还是生成候选？
5. 任务默认是否加 `#task`、日期、项目链接、优先级？
6. 未完成任务是否滚动到次日？由谁决定，怎样避免重复？
7. 跨午夜记录按输入时间、事件发生时间还是当前 Daily 归档？默认时区是什么？
8. 是否需要晨间计划、晚间整理或两者；频率和提醒方式是什么？

### 4.3 Reflection、Review 与 Self

1. Reflection 与 Daily 的边界是什么？是自由写作、结构化反思还是针对事件的问题引导？
2. 需要哪些 Review 节奏：周、月、季度、项目后、学习后？
3. 哪些指标值得回顾，哪些量化会造成负担或误导？
4. Review 应只总结，还是必须生成决策、下一步或实验？
5. 哪些长期信息值得写入 `self/`：方向、约束、能力、稳定偏好、当前重点？
6. 个人信息多久复查一次？旧信息是覆盖、保留历史还是标为失效？
7. 对健康、情绪、财务、关系等敏感主题有什么读取和写入边界？

## 8. 第 5 轮：AI 协作契约

### 5.1 默认行为与权限

1. 默认更偏向“先提议、确认后执行”还是“执行后报告”？请按动作分类，而非只选一个全局模式。
2. 以下哪些可以一键自动发送，哪些必须预览确认：检索、整理 Daily、创建 Wiki、更新 Study Guide、写项目日志、批量迁移、删除 Capture？
3. 哪些动作必须二次确认：覆盖大量正文、移动文件、删除、写入 `self/`、创建后台任务？
4. 当信息不足时，AI 应优先追问、给带假设的草案，还是只指出缺口？
5. AI 发现系统问题但用户只要求回答问题时，应只报告还是可顺手修复？

### 5.2 输出风格

1. 默认语言、中英文术语和文件命名偏好是什么？
2. 默认回答长度、结构密度和语气是什么？不同工作流是否不同？
3. 你偏好结论先行、推理过程、操作步骤、问题引导中的哪种组合？
4. 何时必须引用来源或链接到原文？内部笔记和外部来源应如何区分？
5. 你不喜欢的 AI 习惯有哪些：重复、过度标题化、泛泛鼓励、无关扩展、过度谨慎等？
6. 给出三条你希望系统长期遵守的“像我一样工作”规则。

### 5.3 模型、速度与成本

1. 日常整理、复杂研究和后台生成分别更看重速度、质量还是成本？
2. 是否接受按任务自动选择模型？如果接受，哪些任务必须使用高质量模型？
3. 后台任务可运行多久？失败后是否自动重试，何时通知？
4. 是否允许联网核验？哪些主题必须联网，哪些内容不得外发？

### 5.4 检索与证据

1. 默认更看重近期、来源权威、与当前项目相关，还是与你明确确认的兴趣相关？
2. 默认返回几条内部证据才合适？答案中是否需要显示 Vault 路径、行号或更新时间？
3. `self/`、`life/` 是仅在明确点名时读取，还是个人化任务可按最小范围自动读取？
4. 外部剪藏、Feed、自己的总结和已核验资料应采用怎样的可信度顺序？
5. 找不到证据时，AI 应给一般性答案、联网搜索、追问，还是停止并说明缺口？

## 9. 第 6 轮：模板、入口与信息架构

1. 真正需要快捷入口的 3–5 个动作是什么？按使用频率排序。
2. 每个动作的首选入口是什么：Dashboard、Claudian、命令面板、QuickAdd、模板、手机分享菜单？
3. 每个入口可接受几步？希望系统记住哪些上次选择？
4. 模板更适合“极简空白骨架”还是“问题引导”；哪些笔记需要两种模式？
5. 哪些标题和属性需要用户看见，哪些应由系统维护？
6. 目录和类型命名是否符合你的直觉？哪些词让你犹豫？
7. 链接、标签、目录、Base/Dataview 各自应该承担什么职责？
8. 是否需要统一的命令/预设注册表，让不同入口调用同一行为？
9. 哪些插件是核心，哪些重复、偶尔使用或希望移除？
10. 移动端哪些功能必须可用，哪些可以只在桌面端完成？

## 10. 第 7 轮：迁移、实验与验收

1. 优先改造哪三条黄金路径？其他功能可以延后多久？
2. 是先在测试 Vault 试用，还是对正式 Vault 做小范围灰度？
3. 现有测试/UAT、错误 Clippings、旧 Skills 和无名文件如何处理？
4. 哪些内容必须备份，回滚窗口需要多久？
5. 哪些偏好先作为 1–2 周实验，而非永久默认？
6. 每条黄金路径用哪个真实案例验收？
7. 哪些指标代表改善：完成时间、点击数、返工次数、笔记复用、检索命中、主观负担？
8. 什么结果会让你决定撤销某项改动？

## 11. 访谈产物

访谈完成后应生成并由用户确认：

1. **个人偏好清单**：全局、领域、工作流、例外、敏感边界和失效规则。
2. **黄金路径地图**：触发入口、上下文、动作、确认点、输出、后续去向。
3. **预设矩阵**：学习深度、知识粒度、引用、语言、长度、模型、自动化等级。
4. **Skill 变更集**：保留、精简、拆分、新增、退役及触发边界。
5. **模板与入口变更集**：canonical/interactive 归一，快捷入口和移动端策略。
6. **提示词架构**：共享规则、任务指令、用户偏好、运行时上下文的组合顺序。
7. **迁移与清理计划**：范围、备份、dry run、正式执行、回滚。
8. **验收套件**：真实场景、反例、结构检查、权限检查和回归测试。

## 12. 回答记录格式

每轮回答整理为以下决策单元：

```yaml
id: PREF-001
topic: daily.preserve_raw_words
state: confirmed
scope: workflow:organize-daily
rule: "AI 整理 Daily 时保留用户原话，只在受管理区域生成摘要。"
source: "访谈第 4 轮，用户原话……"
confirmed_at: 2026-08-23
exceptions:
  - "用户明确要求润色原文时可改写指定段落"
positive_example: "……"
counterexample: "……"
review_at: null
```

只有经用户确认的决策单元才能进入正式偏好文件或成为系统默认值。
