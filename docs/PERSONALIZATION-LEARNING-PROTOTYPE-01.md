# 学习材料原型 01：AI Agent Skill

> 日期：2026-08-24  
> 输入：正式 Vault `Clippings/WeChat Article Skills.md`  
> 来源性质：第三方网页剪藏，带有产品宣传表述；本实验不联网核验其功能声明  
> 目的：只比较内容组织方式，不写入正式 Study Guide。

## 为什么选择它

它是现有 Vault 中贴近 AI/Agent 方向、内容完整且尚未被当前 Study Guide 模板加工的真实材料。与 `simple`、`slides` 等导入 fixture 相比，它更适合测试“什么样的学习正文真的有帮助”。

## 原型一：自然解释

这篇文章真正值得提炼的，不是“公众号排版可以更漂亮”，而是一种 Agent Skill 的分工方式：把少数会实质改变结果的选择——风格、发布方式、布局方式——放在工作流入口，其余重复劳动交给系统完成。

模型负责理解文章语义和选择视觉表达；Skill 负责记住微信编辑器的限制与执行顺序；确定性工具负责生成兼容 HTML、处理图片、注入编辑器或调用发布接口；Git 则负责版本追踪和回退。这样，AI 的价值不只是生成文本，而是把“理解意图—遵守平台约束—执行副作用—保留恢复能力”连成一条可完成的工作流。

这对 OKF 的启发很直接：偏好应事先统一配置，普通任务不再重复询问；AI 根据材料决定正文结构，Engine 负责写入、校验和回滚。最终标准应是内容是否帮助理解或行动，而不是模板栏目是否全部填满。

文章本身仍缺少关键证据：没有说明兼容边界、失败处理、凭据安全、发布确认、实际测试范围，也没有证明对比表中的优势。因此这些内容只能作为产品主张，不能当作已核验事实。

## 原型二：从 OKF 当前问题切入

为什么模型能力很强，生成的辅助学习材料仍可能没帮助？问题往往不在模型，而在 Skill 把“完成任务”定义成了“填完一套格式”。于是简单材料也会被扩写成学习目标、核心概念、自测、记忆卡片和总结，结构看起来完整，却没有增加多少理解。

这篇公众号排版案例提供了另一种定义方式：用户真正要的结果是“文章进入公众号后台，兼容、可用、效果好”，而不是完成若干排版步骤。Skill 只收集会改变结果的信息，再自动完成 HTML、图片、注入、发布和版本追踪。

套回 OKF，生成学习材料的完成标准也应该改成：“提取这份材料最值得理解、最容易误解或最能迁移的内容，并让用户能够继续追问或使用。”标题、表格、公式、代码、自测都只是按需工具，不是必填栏目。写入与校验可以自动完成，恢复能力放在后台，不用每次打断用户确认。

文章中“先确认风格、发布方式、布局方式”的流程仍偏人工。按照当前确认的高自治偏好，这些选择更适合保存为长期预设，只有材料真的需要例外时才临时询问。
